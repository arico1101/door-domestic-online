# トビラ 国内版 オンライン

各自の端末からルームに入って遊ぶ、教育すごろく「トビラ 国内版」（16〜45歳・36マス・2〜6人・約25分）。
Cloudflare Workers + Durable Objects（SQLite バックエンド・無料枠）で動く。
公開予定URL：https://tobira-domestic.tobira-online.workers.dev

```bash
npm install
npx wrangler dev        # http://localhost:8787
npm run storybook       # http://localhost:6006（画面を状態別に確認する）
```

ゲームの中身（ルール・家庭カード・トビラ・できごと・奨学金の返済・ネタバラシの文言）の正は、
1画面版 `door-domestic-game` の `index.html`。オンライン版はそれを移したもので、
作り（通信・進行役メニュー・Storybook・テスト・自動デプロイ）は、せかい版オンライン `door-world-online` にそろえてある。

## 遊び方

1. 進行役が公開URLを開き、名前を入れて「ルームをつくる」。6文字の「あいことば」が出る
2. 参加者は各自のスマホで同じURLを開き、名前とあいことばを入れて「ルームに参加」
3. 2〜6人そろったら、進行役が「ゲーム開始」（死別・被災のライフイベントを入れるかは、ここで進行役が選ぶ）
4. 各自の端末に家庭カードが出る。全員が「OK、覚えた」を押すと始まる
5. 手番の人だけがサイコロを回し、トビラを選ぶ。ほかの人の画面には「○○さんが えらんでいます…」とだけ出る
6. 全員が45歳でゴールしたら結果発表 → ネタバラシ → トビラ一覧 → ふりかえりタイム

- 上の名前を押すと、その人の家庭カード（名前・まち・物語・仕送り）が見られる
- 右上のカードのボタンで自分の家庭カード、？であそびかたを見られる
- 国内版は日本語だけで遊ぶ（せかい版オンラインにある English の切り替えはない）

### 秘密にするもの

1画面版のルール「カードは見せ合ってOK。でも『とくい』だけは本人だけの秘密」をそのまま守る。

| 情報 | だれに届くか |
| --- | --- |
| 家庭カードの境遇（名前・まち・物語・仕送り） | 配られた時点で全員 |
| 「とくい」（`perk`・`perkText`） | 結果発表まで本人だけ |
| 見えない選択肢のタグ（`hide`・`hidden`）と「見えなかった」数 | 結果発表まで本人だけ |
| トビラの選択肢とその状態（開く／カギ不足／？？？） | 手番の本人だけ。ほかの人にはトビラの名前だけ |
| 見え方・とくいにふれる注記（`pnote`・`pnotes`） | 本人だけ |

サーバーが状態を送るとき、接続ごとに取り除いている（`src/index.js` の `publicCard()`・`publicPlayer()`・`pendingFor()`）。
`publicCard()` に `perk` などを足すと種明かしがこわれる。`test/play.mjs` と `test/ops.mjs` が毎回これを確かめる。

### 進行がとまったときは 🛠（進行役メニュー）

| こんなとき | やること |
| --- | --- |
| 手番の人の端末が落ちた・席を外した | 🛠 →「○○さんの番をとばす」 |
| カード確認が終わらない人がいる | カード確認の画面か 🛠 →「まだの人を待たずに始める」 |
| まちがえて入った人／途中で帰る人がいる | ロビーでは名前の右の ✕、始まったあとは 🛠 →「外す」（結果発表にも出ない） |
| 進行役をだれかに任せたい | 🛠 →「ゆずる」 |
| 進行役の端末が落ちて戻れない | 残った人の待機画面に「👑 進行役を引きつぐ」が出る |
| 最初からやり直したい | 🛠 →「ロビーにもどす」（途中でも押せる） |

- 手番の人が切断していると、上の帯に「⚠️ 切断中」と出る
- **通信が切れても**、同じ端末で同じURLを開き、同じあいことばで「ルームに参加」すれば元の席に戻れる
- **途中参加はできない**。始まったあとに新しい端末で入ろうとすると、ことわりの文言が出る（満員の6人のときも同じ）
- 同じ端末で2人分遊ぶときは、URLに `?pid=なにか` を付けると別プレイヤーになる

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `src/index.js` | Worker + Room（Durable Object）。乱数・判定・進行はすべてここ |
| `public/rules.js` | サーバーと画面が共有するルール・文言・盤面データ・`MODES` |
| `public/app.js` | クライアント（表示と入力だけ） |
| `public/index.html` | 画面の骨格とCSS（1画面版と同じ淡いブルー・Zen Maru Gothic） |
| `public/se.js` | 効果音。音のファイルは持たず、WebAudio でその場で組み立てる |
| `public/chars/` | プレイヤーのキャラ絵（`p1`〜`p6` × face/joy/fun/sad/angry）。1画面版と同じ絵 |
| `storybook/` | 画面を状態別に確認するストーリー（`stories/`）と雛形（`fixtures.js`）、整合チェック（`validate.mjs`） |
| `test/play.mjs` | 通しプレイ（`N=人数`）。結果発表まで進め、その間ずっと秘密がもれていないかを見張る |
| `test/ops.mjs` | 進行役の操作・選択肢と「とくい」の秘匿・切断からの復帰・途中参加不可 |
| `.github/workflows/deploy.yml` | `main` への push で公開URLへ自動デプロイ |
| `wrangler.toml` | Worker 名 `tobira-domestic`。Durable Object は SQLite バックエンド（無料枠の条件） |

### モードについて

国内版の盤面は1種類だけだが、せかい版オンラインと同じく `public/rules.js` の `MODES` にまとめてある
（盤面・年齢・章・エンディング・人数・重いできごとが起きはじめるマス・ゴールで奨学金を清算するか）。

**「いま選ばれているモード」をモジュール変数に置いてはいけない。**
Durable Object は1つの isolate で複数のルームを動かすので、サーバー側は必ず引数で渡す（`R.mode(g.mode)`）。
画面側は1ゲームしか描かないので、`public/app.js` の `M` に持たせてよい（状態が届くたびに入れかえている）。

盤面のマス数を変えるときは、`public/app.js` の `LAY_WIDE`・`LAY_TALL` も直す。
**1章＝6マスは守ること**（PCは6列、スマホは3列。章ラベルの位置決めがこれに依存している）。

## 設計の決めごと

1. **判定はすべてサーバー。** クライアントを改造しても、他人のカードは見えず、手番も奪えない
2. **できごとの確率は全員おなじ。** できごとカードは全員が同じ山から引く。家庭によって山を変えない
3. **秘密を守る。** 上の表のとおり。結果発表で全員分を公開する
4. **「早すぎる結婚」は扱わない。** 国内版にもその要素はない（足さないこと）
5. **デザインは1画面版と同じ。** 淡いブルー・Zen Maru Gothic・手描き風のSVGアイコン・キャラ絵

### 1画面版から変えたところ

- **できごとの山**：1画面版は「見えていない選択肢が無い家庭」には情報系のカード（情報・進学フェア）を引かせなかった。
  家庭によってできごとの出かたが変わるので、オンライン版は全員が同じ山から引く。見えない選択肢が無い人が情報カードを引いたときは、話を聞くだけで数字は動かない
- **「見えるようになった」の数**：1画面版はタグの数を数えていたが、これから出会う「？？？」の選択肢の数を数える（せかい版オンラインと同じ）。
  家庭カードの「まだ見えていない選択肢」も、同じ数え方
- **死別・被災・役所の封筒**：トビラではないライフイベントなので、結果発表の「出会ったトビラ」には数えない（1画面版は死別・被災を数えていた）
- **給付型奨学金の注記**：「制度を知っている」とくいが理由で給付型になったときは、とくいが分かってしまうので本人にだけ出す
- **結果発表**：秘密だった「とくい」を各自のカードに出す（1画面版は口頭で見せ合っていた）
- **ゴールの順位**：途中で外された人は数えない

## テスト

`npx wrangler dev` を起動したうえで：

```bash
for n in 2 3 4 5 6; do N=$n node test/play.mjs; done
node test/ops.mjs
node storybook/validate.mjs
npm run build-storybook
```

`npm test` で通しプレイ（2〜6人）と `ops.mjs` をまとめて回せる。
8787番が別のサーバーでふさがっているときは `npx wrangler dev --port 8790` で起動し、
`HOST=ws://localhost:8790` を付けてテストを走らせる。

## デプロイ

`main` に入った変更は、GitHub Actions（`.github/workflows/deploy.yml`）が公開URLへ自動で反映する。
Actions の画面から Run workflow で手動実行もできる。

リポジトリの Settings → Secrets and variables → Actions に、次の2つのシークレットが必要：

- `CLOUDFLARE_API_TOKEN`（Workers を編集できる権限のトークン）
- `CLOUDFLARE_ACCOUNT_ID`

手で出すときは `npx wrangler deploy`（Cloudflare にログインずみであること）。
